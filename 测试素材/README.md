# 测试素材

领域与仓库里的订单协同一致：A公司低压电器。客户是成套厂、经销商、盘厂，商品是小型断路器、塑壳断路器、漏电断路器、框架断路器、接触器、电流表、电能表。上传时聊天记录用 TXT，订货表用 XLSX，产品要求用 PDF。

单价和定金是按公开价带编写的示例，不是合同原件。电话都是 1380000 开头的虚构号码。

## A 完整协作三阶段

目录：`A-完整协作三阶段`

同一笔订单 ORD-418，客户青禾成套，联系人采购周宁，电话 13800001001，销售林晓。产品是小型断路器，80 件，含税单价 12.80 元，订单交期 2026-12-08，在手数量 120，最早可完工日期 2026-11-08。这不是库里的 ORD-018。

三份聊天各自都写全了新建客户的必填项：客户名称、订单号、数量、订单交期、在手数量、最早可完工日期。工作台「新建客户」里选「根据文本或文件」，任一份都可以直接提炼并建立，不用再补空项。图片、PDF 和录音也走同一入口。

系统没有单独的三阶段字段。订单状态用的是待确认、已确认、待确认取消、已取消、已关闭。这三个文件按过程拆开，每个文件只有该阶段的消息：

1. `01-询价接洽-聊天记录.txt`：询价和报价，只记成预订单，还没确认。
2. `02-确认下单-聊天记录.txt`：内部审批通过，订单标成已确认。
3. `03-交付结案-聊天记录.txt`：80 件到货点收，全部交付并结案。

目录：`C-订单中断`。文字和电话是同一笔 ORD-430，但内容相反：文字聊天是合作，电话音频是取消。

- `中断沟通-聊天记录.txt`：合作还在进行。江北盘厂采购赵敏，电话 13800001003。框架断路器 630 安 3 极，6 台，订单交期 2026-11-28，定金 3000 元已付。聊天里不取消。
- `产品要求.pdf`：与聊天同一笔活单的规格、数量、订单交期和定金。不要把取消写进 PDF。
- `音频1.m4a`：用这一份，不要再用上一级目录里的副本。已核对的转写是：客户找到了更好的供货方，打算取消上一笔，定金不用退，感谢合作，有机会下次再合作。取消只出现在这段电话里。

上一级的 `测试素材/音频1.m4a` 仍保留，内容与 C 目录里的文件相同，没有重新编码。

## D 三类洽谈

目录：`D-三类洽谈`。这三件都只生成草案或待办，确认前不写订单。

1. `01-线下洽谈-聊天记录.txt`：挂在 ORD-018 上。B老板说明天不改 100 件和订单交期，并约定星期二 2026-11-03 上午 9 点派人到厂里当面谈。抽取用的就是这段原文。系统应单独抽出洽谈任务（采购周宁、销售林晓、地点、时间、谈框架断路器备货），不能只因为它不是数量或交期就丢掉。
2. `02-规格未说清-聊天记录.txt`：澄江新客以前没有订单。只说「要一批断路器，尽快」。不要挂到 ORD-018 上借它的规格。先建没有订单的客户，再 `POST /customers/{客户id}/intake` 提交这段话。系统应列出缺规格、数量、要求交期，不能补型号、件数或日期。`POST /customers/{客户id}/intake/{草案id}/confirm` 之后只产生没有订单号的待办，不新建订单。
3. `03-沿用上次规格-有历史.txt`：青禾成套说「像上次一样」，再来 40 件，要求交期 2026-12-02。抽取用的就是这段原文。有历史时规格沿用该客户上一笔 ORD-018 的小型断路器，并写明订单号。确认前不新建、不改写。
4. `03-沿用上次规格-无历史.txt`：同一句「像上次一样」，但是澄江新客没有历史。只能追问规格，不能猜成某一只断路器。40 件和 2026-12-02 是原话里有的，可以复述，不能当成已经建好的订单。
