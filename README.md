# 单迹

从聊天、表格和通话转写里识别订单变化，标出数量、交期和库存冲突，生成可确认的任务。模型只提出事件草案；写入订单和任务必须经过人工确认。

| | 链接 |
| --- | --- |
| **在线演示** | <https://danji.onrender.com/> |
| **源码仓库** | <https://github.com/Lesring/Danji> |

公网实例由 Render 部署（见 `Dockerfile`、`render.yaml`），默认 `EXTRACT_MODE=fixture`，**不需要**在仓库里填写 API 密钥。免费实例休眠后首访可能需等待几十秒。若需自行部署，用 GitHub 连接 Render Blueprint 即可。

## 你需要配置的内容

默认不用密钥也能演示。配置都写在 `backend/.env`（由 [backend/.env.example](backend/.env.example) 复制）。

TXT、CSV、XLSX、DOCX 和带文字层的 PDF 在本地解析，不需要新密钥。需要外部接口时再填写：

1. 把聊天或文件解析成订单事件：填写 `LLM_API_BASE`、`LLM_API_KEY`、`LLM_MODEL`，并把 `EXTRACT_MODE` 从 `fixture` 改成 `llm`。接口需要兼容 OpenAI 的 `/chat/completions`，`LLM_API_BASE` 要带版本前缀，例如 `https://api.openai.com/v1`。留空或保持 `fixture` 时按内置案例抽取，不访问模型。
2. 图片和没有文字层的 PDF：填写 `OCR_API_KEY`。`OCR_API_BASE` 填火山方舟版本前缀 `https://ark.cn-beijing.volces.com/api/v3`（留空时沿用 `LLM_API_BASE`），`OCR_MODEL` 默认 `doubao-seed-2-0-mini-260428`。请求发到 `{OCR_API_BASE}/responses`，图片用 `input_image`。留空时这两类会提示未配置，其他文件仍可解析。
3. 录音：填写 `ASR_API_KEY`。`ASR_API_BASE` 与图片相同，留空时沿用 `LLM_API_BASE`，`ASR_MODEL` 默认 `doubao-seed-2-0-mini-260428`。同样请求 `/responses`，本地录音放在 `input_audio` 的 data URL 里。留空时上传音频会提示未配置，文本和文档不受影响。
4. 主接口超时、连不上或返回 402、429、5xx 时，会再请求一次 `{ARK_FALLBACK_API_BASE}/responses`，模型默认 `doubao-seed-2-0-lite-260428`。成功的响应不会改走备用。

规则检测和确认写入不依赖模型。

## 启动

需要 Python 3.11 及以上，以及 Node.js。

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

另开一个终端：

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开 <http://127.0.0.1:5173>（本地开发）。评审可直接打开 **<https://danji.onrender.com/>**（前后端一体，无需单独开 5173）。

## 演示路径

在线或本地均可：工作台里打开 **ORD-018 青禾成套**。这是 A公司存货的一笔小型断路器订单：100 件、订单交期 2026-11-10；本仓在手 120 件，最早可完工日期 2026-11-08。同一商品的在手由各客户共用，其他未关闭订单占用之后，本单可承诺的数量会减少。公网演示预置多客户、多订单（含各订单状态与一条回收站样例）、任务看板四类状态，**ORD-020** 带待审核草案；**澄江新客** 有一条客户接入草案。

进入这张订单的详情，在「录入沟通」里粘贴下面这段聊天，再点「解析为草案」。此时订单数量和交期保持不变，审核页会出现：

```text
客户聊天 · 10:05
这批小型断路器能不能增加到 150 件？最好 11 月 6 日前发出来。

库存表 · 10:12
当前库存 120 件，尚未完成的生产计划需要重新核对。

销售沟通 · 10:20
我先跟客户说了，150 件，11 月 6 日发货。
```

- 数量超过库存、交期早于生产能力、销售承诺未核实
- 销售、生产、订单负责人三条任务建议
- 每条风险和任务都可以打开原始证据

销售承诺只能记录，不能直接改写订单。数量或交期要勾选「采纳到订单」并确认后，才会写入，同时留下修改前后的审计记录。拒绝的任务建议不会出现在看板上。

更多场景（库存内改数量、取消、交期矛盾、责任人不清、线下洽谈等）的原文在仓库 [`测试素材`](https://github.com/Lesring/Danji/tree/main/测试素材) 目录；打开对应订单详情，粘贴到「录入沟通」再解析。**ORD-019 南浦配电** 可演示库存足够时的数量变更；工作台可切换筛选、回收站查看 **ORD-025**。

线下当面洽谈、沿用上次规格同样是把 `测试素材` 里的原文粘贴到 ORD-018 再解析。「线下当面洽谈」会另开一条任务，写明谁、哪一天、到厂里谈什么，不改 100 件和订单交期。「沿用上次规格」把规格对上这一客户的上一笔 ORD-018，确认前不新建订单。没有历史订单、只说「要一批断路器，尽快」时，先建客户、不要带订单，再把聊天交给客户接入；系统只开待办问规格、数量和要求交期，不补型号。

工作台选中订单后，详情里的「历史导入」默认收起。展开后按时间列出每次导入处理后的文字摘要，不显示原始文件。

详情页导入分为「聊天记录」和「文件」。聊天记录可以粘贴，也可以上传 TXT、HTML、JSON 导出。文件支持 CSV、XLSX、DOCX、带文字的 PDF；CSV、XLSX 和 DOCX 表格会保留单元格位置。图片和录音要先配好对应密钥。已转写的通话文本直接粘贴即可。

## 测试

```powershell
cd backend
python -m pytest
```

规则测试不调用模型。接口测试覆盖主案例、确认承诺不改交期、采纳交期、拒绝任务、新消息关联未关闭任务，以及未配置密钥时来源仍会保留。

## 不做的部分

登录、微信或钉钉接入、实时电话、知识库检索和工作流引擎不在这一版里。录音转写和扫描件识别只在填写了对应密钥后可用。

## 演示数据说明

- 全部为**自建虚构样例**（电气类商品、客户名与「A公司存货」备注），**未使用**企业真实订单或未授权数据。
- 公网实例默认 `EXTRACT_MODE=fixture`：内置规则与样例文本驱动抽取，**不调用**外部大模型，评审无需 API 密钥。
- 在线站预置多客户、多订单（含待确认/已确认/待确认取消/已取消/已关闭）、任务看板各状态、回收站 **ORD-025**、**ORD-020** 待审核草案、**澄江新客** 客户接入草案；**ORD-018** 仍保持「空审核」便于按上文粘贴主案例。

## 故障恢复

| 现象 | 处理 |
| --- | --- |
| 打开 danji.onrender.com 长时间加载或 502 | Render 免费实例休眠，**等待 30～90 秒**刷新；仍失败则隔 1 分钟再试。 |
| 页面空白或静态资源 404 | 确认访问根路径 `https://danji.onrender.com/`；本地开发需先 `npm run build` 或由后端 `STATIC_DIR` 指向 `frontend/dist`。 |
| 本地端口占用 | 改 `uvicorn --port` 或 Vite 端口；前端 `.env` 中 API 地址指向后端。 |
| 公网数据与说明不一致 | 以 GitHub **main** 最新部署为准；种子版本见 `backend/app/fixtures/demo.json` 的 `demo_revision`，升级后会自动重灌（用户若清空过工作台则仅保留仓库目录）。 |
| 解析报错但来源已保存 | 来源仍会入库；fixture 模式下检查粘贴文本是否与 README 主案例一致。 |

### AI 工具栈

- **开发：** Cursor（编码、调试、文档）。
- **文本抽取（可选）：** OpenAI 兼容 `/chat/completions`；公网演示为 **fixture**，不访问模型。
- **图片 / 扫描 PDF / 录音（可选）：** 火山方舟 Responses API（`doubao-seed-2-0-mini-260428` 等，见 `backend/.env.example`）。
- **规则与写库：** Python 后端校验库存、交期；人工确认后才写入订单与任务。
